# tool_bridge

## Организация проекта

- По возможности согласуй структуру каталогов с пространствами имён относительно корневого пространства `Topomatic.ToolBridge`.
- Сохраняй прежние пространства имён публичных типов, если их изменение нарушит бинарную совместимость со сторонними плагинами, собранными против старых версий API tool-bridge. В этом случае расхождение со структурой каталогов допустимо.

## Тестируемость и зависимости от Robur

- Проектируй код так, чтобы его логику можно было удобно проверять в изолированных тестах без запуска Robur.
- Изолируй обращения к работающей платформе (активному проекту, окнам, глобальному состоянию) в сервисах. Тестируемая логика должна получать эти сервисы через принятый в проекте механизм внедрения зависимостей (DI), позволяющий подставлять тестовые реализации.
- Используй существующие сервисы; при необходимости добавляй новые интерфейсы и реализации.
- Напрямую используй модели и типы Robur, которые можно создавать и использовать в изолированных тестах. Не вводи обёртки только из-за принадлежности типа к Robur.

## Написание тестов

- Не начинай писать тесты автоматически. Сначала кратко опиши пользователю предлагаемые проверки, запроси явное подтверждение и дождись его.
- Размещай тесты в существующих тестовых проектах каталога `tests/tool_bridge` от корня `robur-mcp` (`C:\Topomatic\robur-AI\robur-mcp\tests\tool_bridge` в текущем окружении).

## Добавление ссылок на сборки Robur

### Оформление ссылок

- Добавляй сборки в `Topomatic.ToolBridge.csproj` элементами `Reference`. Для `Topomatic.*` указывай полное имя сборки в `Include` по данным DLL, `SpecificVersion=False` и `Private=False` (Copy Local отключён: сборки предоставляет Robur).
- Задавай `HintPath` только через `$(RoburReferencesPath)\ИмяСборки.dll`, чтобы сохранить переключение режимов сборки.
- Для поставляемой с платформой `Newtonsoft.Json` сохраняй исключение: `SpecificVersion=True`; путь также задаётся через `RoburReferencesPath`, а `Private=False`.

### Режимы сборки

Пути ниже указаны от корня `robur-mcp`.

- По умолчанию `RoburReferencesPath` указывает на реальные DLL в `Out/Bin`.
- При `UseRoburReferenceAssemblies=true` используются заглушки из `tool_bridge/references`. Этот режим включает `scripts/build_tpm.py`; проект проверяет наличие заглушек для `Topomatic.*` и `Newtonsoft.Json`.
- Заглушки содержат метаданные API без реализации методов. Используй их только для компиляции, а не для выполнения кода или тестов, которым нужны реализации Robur.

### Обновление заглушек

- После добавления ссылки или обновления исходных DLL уведомляй пользователя о необходимости обновить заглушки и пересоздании каталога `tool_bridge/references`. Запроси явное подтверждение и дождись его; не запускай генерацию автоматически.
- Для генерации нужны реальные DLL в `Out/Bin` и Refasmer (установка: `dotnet tool install --global JetBrains.Refasmer.CliTool`).
- После подтверждения запускай `python scripts/generate_references.py` из корня `robur-mcp`. Скрипт получает список DLL из `HintPath`, начинающихся с `$(RoburReferencesPath)\`, в файле проекта; отдельный список поддерживать не нужно.
