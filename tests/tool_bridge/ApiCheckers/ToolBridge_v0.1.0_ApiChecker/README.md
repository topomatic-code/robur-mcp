# Проверка совместимости ToolBridge 0.1.0

Команда `tool_bridge_v0.1.0_api_check` возвращает `string[]`: по одному результату
для каждой из десяти групп. `ToolBridge.Tests.ApiCheck_v0_1_0` вызывает команду
один раз на блок и отображает каждую группу как отдельный тест. Сводка блока
содержит количество пройденных и непройденных групп (всего десять: семь проверок API и три интеграционные).
Проверяются статусы, формат, отсутствие дубликатов и наличие всех групп.
Отсутствующий или повторный результат делает соответствующий тест непройденным;
ошибка вызова команды или некорректный формат отчёта делает непройденными все тесты.

| Группа / функция | Проверяемый API |
| --- | --- |
| `CheckToolProvider` | Наследование от `ToolProvider`, все четыре пары getter/setter с null, сигнатура обработчика `Dictionary<string, object> -> object`. Не создаёт хранилище, не получает логгер и не использует ToolDefAttribute. |
| `CheckToolDefAttribute` | Конструктор, все свойства и применение атрибута к методу обычного класса, без наследования от ToolProvider. |
| `CheckToolProviderContextIntegration` | Integration.ToolProviderContext: передача настоящих AppHost, ObjectStorage и ToolBridgeLogger в контекст провайдера и проверка идентичности ссылок. |
| `CheckDwgStorageIntegration` | Integration.DwgStorage: FindEntity, поиск по GUID, кеш ObjectStorage, отсутствующий GUID и объект из другого чертежа. |
| `CheckObjectStorage` | Конструктор, обе перегрузки AddObject/HasObject/RemoveObject, GetObject, GetGuid, Clear; повторное использование, дубликаты, отсутствующие значения и null. |
| `CheckLogger` | Instance, CreateLogString, Log. В консоль Robur выводится одна диагностическая строка. |
| `CheckJson` | Все 19 методов JsonUtils: скаляры, объекты, векторы, массивы, значения по умолчанию, преобразования и ошибки; в том числе усечение дробного числа, предусмотренное 0.1.0. |
| `CheckDwg` | 23 метода DwgUtils без FindEntity: получение чертежа без активного вида, типы и сериализация сущностей, границы, слои, цвета, четыре парсера перечислений. |
| `CheckSmdx` | CreatePropsArray и CreateImElementObj: группировка свойств, значения, теги, единицы, имя и границы элемента. |

## Как обнаруживаются нарушения совместимости

Плагин компилируется против локальной заглушки `Topomatic.ToolBridge` **0.1.0.0**
с фиксированным PublicKeyToken. Проверки вызывают старый API напрямую: заменять
эти вызовы поиском методов через reflection нельзя, иначе теряется проверка
бинарных ссылок старого плагина.

В проверках публичного API reflection используется для запуска независимых групп и чтения полей
анонимных объектов, возвращаемых API. Методы, необходимые совместно для одного механизма (например, создание хранилища и операции с ним), остаются в одной группе. Внутренние зависимости реализации ToolBridge не подменяются. Проверка null-accessors не доказывает сохранение ненулевых ссылок — это проверяет отдельный интеграционный тест.

Каждая группа имеет отдельную границу
перехвата исключений и запрещает встраивание (`NoInlining`). Ошибка загрузки типа,
отсутствующий метод или неверный результат помечают группу как `fail`; остальные
группы продолжаются. Внутри группы выполнение останавливается при первой ошибке.

Формат строки: `success: [Group] описание` или `fail: [Group] исключение`.
Неизвестный статус, пустой ответ или неполный набор групп не считаются успехом.
Если сам плагин не загрузился из-за политики привязки сборок Robur, это проявится
ошибкой вызова команды либо отсутствием результатов в `ToolBridge.Tests`.

## Интеграция старого провайдера без Domain

`Integration_LegacyProviderNoDomain` проверяет два метода провайдера, скомпилированного
против ToolBridge 0.1.0. Атрибуты не задают Domain; два метода позволяют проверить
сортировку даже при отсутствии сохранённых настроек.

Этапы: обнаружение через настоящий broadcast `tool_request`, преобразование атрибутов
в определения инструментов, загрузка и сортировка настроек, `list_tools`, `call_tool`
и проверка аргумента/результата и передачи контекста в старый обработчик.
В ошибке указано название этапа. Отсутствие Domain не исправляется самим тестом.

Это интеграционный адаптер к внутренней инфраструктуре **0.2**: reflection используется
для ToolCollector, ToolSettings, ToolManager и диспетчера запросов. Публичный контракт
старого провайдера остаётся прямыми бинарными ссылками на 0.1.0. Изменение внутренних
имён инфраструктуры может потребовать обновления адаптера и само по себе не означает
нарушение публичного API. Этот дополнительный тест не предназначен для хоста 0.1.

Перед запуском остановите Tool Bridge/MCP-сервер; для этапа call_tool откройте видовой
экран Robur. Тест использует временный набор инструментов и восстанавливает исходные
коллекции, включая несохранённые настройки, в finally. Файлы настроек не сохраняются.
Регистрация пробного провайдера включается только на время тестового broadcast;
при обычном запуске Robur он не добавляется в список инструментов.

Диспетчер настоящих запросов вызывается в потоке команды Robur с JSON-сериализацией,
без запуска pipe-сервера. Транспорт pipe, Python MCP-сервер и внешний MCP-клиент этим
тестом не проверяются. Тест не запускает и не останавливает рабочие серверы.
Обновлять нужно обе DLL и файл `tool_bridge_v0.1.0_api_checker.plugin`.

## Тестовые данные и ограничения

Создаётся отдельный Drawing, который освобождается после проверки. Активный проект
не изменяется. Для текста используется один из уже загруженных шрифтов Robur.
Тестовое растение содержит обязательные свойства и пустое графическое представление,
поэтому не требует установки библиотеки посадок. Тела и TLC-модель создаются в памяти.
Хранилища объектов также отдельные; глобальное хранилище не очищается.

Проверяется весь объявленный публичный API ToolBridge 0.1.0 (79 членов, включая
аксессоры и публичные конструкторы), а также защищённый конструктор ToolProvider.
Сценарии проверяют работоспособность этих вызовов и типовые результаты/ошибки;
это не исчерпывающий перебор всех геометрий, моделей и входных данных.
Pipe-протокол и внешний MCP-сервер не входят в этот
публичный C#-контракт. Проверка не запускает и не останавливает сервер.

Заглушка Newtonsoft.Json 13.0.0.0 взята из зависимости исходной версии ToolBridge
(пакет 13.0.4). Она нужна для JValue/JObject/JArray той версии, с которой работали
старые плагины. Заглушки используются только компилятором (`Private=False`);
при запуске нужны настоящие DLL Robur/ToolBridge и совместимая зависимость Newtonsoft.
Все заглушки зависимостей находятся в собственной папке `references` этого проекта и подключены относительными путями. Проект не зависит от каталога `tool_bridge/references`.

## Проверка полноты покрытия

После сборки выполните в PowerShell 7:

```powershell
.\VerifyApiCoverage.ps1 -CheckerAssembly <путь-к-собранной-DLL>
```

Утилита сравнивает полные сигнатуры из старой заглушки с бинарными ссылками в
собранном плагине, включая перегрузки и аксессоры. Ожидается 80 ссылок и 0 пропусков.
Она также проверяет версию ссылки на ToolBridge. Это статическая проверка покрытия;
фактическую совместимость проверяет запуск плагина в нужной версии Robur.

Для проверки новой версии ToolBridge используйте неизменную сборку этого плагина,
собранную против 0.1.0, и подменяйте только установленный ToolBridge. Пересборка
плагина против новой версии не проверяет совместимость уже выпущенных плагинов.
