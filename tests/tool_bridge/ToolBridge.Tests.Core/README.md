# Проверки основного функционала ToolBridge

Проект `ToolBridge.Tests.Core` предназначен для тестирования текущего функционала ToolBridge. Он содержит проверки DI-контейнера в [ContainerTests.cs](DependencyInjection/ContainerTests.cs), инструментов AlgTools в [Tools/AlgTools](Tools/AlgTools) и DwgTools в [Tools/DwgTools](Tools/DwgTools). Новые группы проверок добавляйте отдельными классами и регистрируйте в [Module.cs](Module.cs).

[Общие инструкции по написанию и запуску тестов](../README.md).

## Зависимости и условия запуска

Проект ссылается на текущий `Topomatic.ToolBridge.csproj` и общую инфраструктуру `ToolBridge.Tests`. Сборки Robur и Newtonsoft.Json подключены из `robur-mcp/Out/Bin` с `Private=False`. Зависимость ToolBridge собирается в общий каталог `Out/Bin`.

[Module.cs](Module.cs) регистрирует проверки контейнера, AlgTools и все 25 групп DwgTools через broadcast `test_request`. Для запуска установите DLL проекта и [файл регистрации](tool_bridge_tests_core.plugin) вместе с текущим ToolBridge и инфраструктурой тестов.

Открытый проект или видовой экран Robur для этих проверок не требуется. Каждый тест создаёт собственный контейнер. Тесты AlgTools используют [AlgToolsFixture](Tools/AlgTools/AlgToolsFixture.cs): локальный `IAlignmentProvider` и реальные модели трассы, конструкций и выражений Robur в памяти. Тестовый наследник `RoadAlignment` пропускает создание стилей отображения, требующих глобальных сервисов приложения. Контейнер работающего приложения не изменяется.

## Проверяемые сценарии

### DwgTools

В [Tools/DwgTools](Tools/DwgTools) находится по одному файлу на каждый из 25 инструментов, всего 50 тестовых методов. Проверяются:

- создание и изменение слоёв, активация, удаление и защита системного слоя;
- создание и частичное обновление полилиний, линий, окружностей, текста, мультитекста, таблиц и штриховок;
- геометрия, метаданные, назначение слоя и цвета, сохранение идентичности объектов;
- диапазоны выдачи, стабильность GUID, поиск через хранилище и словарь расширения;
- удаление из чертежа и хранилища, пакетное изменение слоя и цвета;
- подмена каталога штриховок, сортировка, пустой каталог и ошибки провайдера;
- неверные аргументы, отсутствующие сущности, неверный тип и принадлежность другому чертежу.

[DwgToolsFixture](Tools/DwgTools/DwgToolsFixture.cs) создаёт собственный контейнер, локальные `IDrawingProvider` и `IHatchPatternProvider`, реальный `ObjectStorage` и заглушку логгера. Чертёж создаётся лениво; проверкам каталога штриховок он не нужен. Сущности для тестов обновления создаются напрямую, без вызова инструментов создания.

Модели чертежа, сущностей и таблиц настоящие. Шрифт активного стиля заменён тестовым `CadFont` с детерминированными метриками: точность шрифтового рендеринга здесь не проверяется, файлы SPDS/TTF не нужны. Глобальные сервисы приложения и активный чертёж не подменяются.

Для автономного запуска требуется .NET Framework 4.8 и сборки из `Out/Bin`. Перед созданием первого `Drawing` нужно задать `ProcessEnvironment.Current.SetVariable("UserAppDataPath", cacheDirectory, EnvironmentModifier.Process)`, где `cacheDirectory` — существующий доступный для записи временный каталог: конструктор модели использует шрифтовый кеш `cfonts.json`. Эта настройка относится к автономному процессу запуска, а не к тестовой фикстуре. Внутри Robur путь уже настроен.

### Создание экземпляров и внедрение зависимостей

`CheckTransientDependencies` регистрирует цепочку `Root → Branch → ILeaf` и проверяет:

- Разрешение вложенных зависимостей через конструкторы.
- Получение нового экземпляра `Branch` при повторном создании `Root`.
- Отсутствие внедрения в свойство `Root.Property`.
- Ошибку при создании незарегистрированного конкретного типа.
- Ошибку при получении синглтона по отсутствующему идентификатору.

### Синглтоны

`CheckSingletons` регистрирует синглтоны и обычную зависимость между ними. Проверяются:

- Получение одного и того же экземпляра `Root` при 32 параллельных обращениях.
- Внедрение зарегистрированного синглтона `ILeaf` во вложенный объект.
- Разные экземпляры одного сервиса для разных идентификаторов.
- Ошибка разрешения зависимости при наличии нескольких синглтонов одного типа.
- Ошибка получения синглтона с несовместимым запрошенным типом.
- Создание нового экземпляра после повторной регистрации того же идентификатора.

Параллельная часть только получает экземпляры и записывает их в массив. Проверки результатов выполняются после завершения `Parallel.For` в потоке теста.

### Повторная попытка после ошибки

`CheckFailedSingletonRetry` сначала запрашивает синглтон с отсутствующей зависимостью и ожидает `ContainerException`. Затем регистрирует зависимость и повторяет запрос в том же контейнере. Проверка подтверждает, что неудачное создание не блокирует последующее получение экземпляра.

### Конструкторы и ошибки регистрации

`CheckResolutionErrors` проверяет выбор публичного конструктора с наибольшим числом параметров и следующие ошибки:

| Сценарий | Ожидаемое исключение |
| --- | --- |
| Циклическая зависимость `CycleA → CycleB → CycleA` | `ContainerException` |
| Несколько публичных конструкторов с одинаковым максимальным числом параметров | `ContainerException` |
| Отсутствие публичного конструктора | `ContainerException` |
| Незарегистрированный параметр конструктора, даже при наличии значения по умолчанию | `ContainerException` |
| Регистрация интерфейса или абстрактного класса в качестве реализации | `ArgumentException` |
| Регистрация синглтона с идентификатором `null` | `ArgumentNullException` |

## Способ проверки

Положительные сценарии используют `Test.Require` для проверки созданных объектов, ответов инструментов и ссылочной идентичности экземпляров. `Test.Throws<T>` проверяет ожидаемое исключение типа `T` или его наследника. Тексты исключений не фиксируются. Изменённая в тесте культура восстанавливается в `finally`.

### Инструменты AlgTools

Для каждого инструмента выделен отдельный класс в пространстве имён `ToolBridge.Tests.Core.Tools.AlgTools`:

- [GetAlignmentTests](Tools/AlgTools/GetAlignmentTests.cs): фильтрация `usedOnlyConstructions` по умолчанию и явно, полный список, признаки использования, счётчики, повторные назначения и изменение данных между вызовами.
- [GetParametersTests](Tools/AlgTools/GetParametersTests.cs): имена, описания и типы вычисляемых и табличных параметров, отсутствие вычисления значений, удаление параметров и пустые таблицы.
- [GetConstructionTests](Tools/AlgTools/GetConstructionTests.cs): пустые, одиночные и разделённые диапазоны поперечников, пикетаж с ненулевым началом, `compact` по умолчанию и `ast`, приоритеты операторов и скобки, константы и независимость от культуры, сохранение полного AST для неподдерживаемых выражений, вложенные компоненты и сокращённая семантика.

Все три класса проверяют некорректные аргументы и передачу ошибок провайдера. Методы инструментов вызываются напрямую; ответы проверяются через `JObject`. Транспорт MCP и получение трассы из реального проекта в `AlignmentProvider` этим набором не проверяются. Проверки совместимости с API 0.1.0 находятся в отдельном проекте.

При обновлении ранее установленного тестового плагина замените `ToolBridge.Tests.DependencyInjection.dll` и `tool_bridge_tests_dependency_injection.plugin` на `ToolBridge.Tests.Core.dll` и `tool_bridge_tests_core.plugin`. Старый файл регистрации не должен оставаться в каталоге плагинов, иначе проверки контейнера могут зарегистрироваться дважды.
