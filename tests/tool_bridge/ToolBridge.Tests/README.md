# ToolBridge.Tests

После загрузки плагина выполните команду `run_tests` в Robur. Откроется отдельная
Windows-консоль. После просмотра результатов закройте окно или нажмите Enter.
Закрытие консоли не завершает Robur и не прерывает уже запущенные тесты.
Для окна используется встроенный Windows PowerShell; сторонних библиотек нет.
Сообщения передаются по порядку через фоновую очередь. Завершение команды
не ждёт вывода: очередь допечатывается, после чего консоль предлагает закрыть окно.
Ожидание подключения ограничено 15 секундами, отправка одного сообщения —
5 секундами. Если получатель недоступен, передача прекращается без блокировки
Robur; при обрыве консоль предупреждает, что отчёт может быть неполным.

## Объявление тестов

Классы внутри сборки `ToolBridge.Tests` помечаются `[TestProvider]`, методы — `[Test]`.
Методы могут быть приватными или публичными, статическими или экземплярными.
Поддерживаются синхронные методы `void` без аргументов и параметров типа.
Для экземплярных методов нужен конструктор без параметров; он может быть приватным.
Один экземпляр провайдера используется для всего блока. Тесты выполняются
последовательно в потоке команды Robur, в порядке имён классов и методов.
Неподдерживаемые сигнатуры пропускаются с предупреждением.

## Результаты

- `Test.Assert(condition)` или `Test.Assert(condition, successMessage, failureMessage)` — проверка условия.
- `Test.Success(message)` — зелёное сообщение с `✓`.
- `Test.Fail(message)` — красное сообщение с `✗`; метод становится непройденным,
  но продолжает выполняться.
- `Test.Warning(message)` — жёлтое сообщение с `!`; не меняет статус теста.

Исключение также делает метод непройденным; следующие тесты продолжают выполняться.
Метод без ошибок считается пройденным, даже если не вызвал `Assert`.
Счётчики учитывают методы, а не количество сообщений или проверок внутри них.

`Test` предоставляет провайдерам только `Assert`, `Success`, `Fail` и `Warning`.
Единственный служебный метод `Test.GetTestingContext()` возвращает общий
`TestingContext`, в котором хранятся сообщения и счётчики.
Для каждого провайдера запускатель вызывает `BeginTests` и `EndTests` контекста,
а для каждого тестового метода — `BeginTest` и `EndTest`.
`EndTests` возвращает независимый
снимок результатов и сбрасывает состояние. `TestRunner` отвечает за поиск
и вызов методов внутри провайдера. `TestConsole` управляет окном консоли,
цветами, символами и выводит результаты с отдельной сводкой пройденных,
непройденных и (при наличии) невыполненных тестов.
В самих тестах вызывать `BeginTests` и `EndTests` не нужно. Глобальной сводки нет.
Контекст запрещает повторный `BeginTests` внутри блока, `EndTests` во время
выполнения метода и `Skip` вне блока или внутри метода. Такие вызовы выбрасывают
`InvalidOperationException`, сохраняя уже накопленные результаты.

`TestProviders/DemoTests.cs` содержит два демонстрационных блока: успешный
и намеренно проваленный. Их можно удалить вместе со строкой `Compile` в проекте,
когда проверка механизма запуска больше не нужна. `ApiCheck_v0_1_0` выполняется
как отдельный блок из десяти тестов: семь проверок старого API и три интеграционные проверки с префиксом Integration_. Команда вызывается один раз на блок.
Описание сценариев и проверка покрытия находятся в
`../ApiCheckers/ToolBridge_v0.1.0_ApiChecker/README.md`.
