# Тесты ToolBridge

[ToolBridge.Tests.sln](ToolBridge.Tests.sln) объединяет тестовые плагины Robur. Проект [ToolBridge.Tests](ToolBridge.Tests/) предоставляет регистрацию и запуск тестов, атрибут `TestAttribute`, методы проверок `Test` и консоль результатов.

| Проект проверок | Назначение и подробная документация |
| --- | --- |
| [ToolBridge.Tests.ApiCheck_v0.1.0](ToolBridge.Tests.ApiCheck_v0.1.0/README.md) | Сохранение контракта C# API 0.1.0 и интеграция провайдера с ToolBridge. |
| [ToolBridge.Tests.DependencyInjection](ToolBridge.Tests.DependencyInjection/README.md) | Регистрация сервисов, внедрение через конструктор, синглтоны и ошибки DI-контейнера. |

## Сборка и запуск

Для компиляции разместите реальные сборки Robur и его зависимостей в `robur-mcp/Out/Bin`. Все тестовые проекты берут внешние DLL из этого каталога с `Private=False`. Для полного обновления тестов пересобирайте solution вместе с текущим ToolBridge.

1. Откройте `ToolBridge.Tests.sln` и соберите solution. Выходной каталог тестовых проектов — `robur-mcp/Out/Bin` (`../../Out/Bin` относительно этой папки). Зависимость проекта DI также собирает актуальную `Topomatic.ToolBridge.dll` в этот каталог.
2. Установите в Robur актуальную `Topomatic.ToolBridge.dll`, тестовые DLL и файлы регистрации:

   | Сборка | Файл регистрации |
   | --- | --- |
   | `ToolBridge.Tests.dll` | `tool_bridge_tests.plugin` |
   | `ToolBridge.Tests.ApiCheck_v0.1.0.dll` | `tool_bridge_tests_api_check_v0.1.0.plugin` |
   | `ToolBridge.Tests.DependencyInjection.dll` | `tool_bridge_tests_dependency_injection.plugin` |

3. Выполните `run_tests` в Robur. Результаты появятся в отдельной Windows-консоли.

Условия запуска отдельных сценариев описаны в README проектов. Для полного прогона откройте видовой экран Robur: он нужен проверкам вызова и контекста провайдера. Текущие тесты не требуют остановки MCP-сервера.

## Написание тестов

Тестовый проект — библиотека .NET Framework 4.8 с регистрацией плагина Robur. Добавьте его в solution, настройте выходной каталог `Out/Bin` и копирование файла `.plugin`. Подключите `ToolBridge.Tests` и сборки, необходимые для выбранного объекта проверки. Тесты ссылаются на текущий проект ToolBridge. В проверках совместимости эталонные сигнатуры прежней версии хранятся в исходниках и не меняются вслед за реализацией.

Каждый тест должен самостоятельно готовить данные и не зависеть от порядка выполнения соседних методов. Изменяемое состояние освобождайте или восстанавливайте в `finally` либо через `using`. В проверках с параллельной работой дождитесь её завершения и записывайте результаты из потока теста.

Минимальный провайдер:

```csharp
using ToolBridge.Tests;

internal sealed class ExampleTests
{
    [Test]
    internal void CheckOperation()
    {
        var values = new System.Collections.Generic.List<int>();
        values.Add(42);

        Test.Require(values.Count == 1, "Операция должна добавить один элемент.");
        Test.Assert(values[0] == 42);
    }
}
```

Замените демонстрационную операцию вызовом тестируемого кода. Используйте `Test.Require`, если ошибка делает дальнейшие шаги бессмысленными, и `Test.Assert`, если нужно продолжить независимые проверки.

## Регистрация и выполнение

Добавьте в проект ссылку на `ToolBridge.Tests`. Пометьте методы атрибутом `[Test]`: поддерживаются объявленные непосредственно в классе синхронные методы `void` без аргументов и параметров типа. Методы могут быть публичными или непубличными, статическими или экземплярными. Неподдерживаемые сигнатуры, включая `async void`, пропускаются с предупреждением.

Обработчик broadcast `test_request` получает в `args[0]` список `List<object>`. Добавьте в него новый экземпляр провайдера тестов и свяжите обработчик с broadcast в `.plugin`. Пример — [Module.cs](ToolBridge.Tests.ApiCheck_v0.1.0/Module.cs) и [файл регистрации ApiCheck](ToolBridge.Tests.ApiCheck_v0.1.0/tool_bridge_tests_api_check_v0.1.0.plugin).

Раннер выполняет классы и методы последовательно по именам в потоке команды Robur. Все методы одного блока используют зарегистрированный экземпляр. Повторная регистрация типа и `null` считаются ошибками регистрации. Запись результатов из фоновых потоков не поддерживается.

## Результаты

| Метод | Поведение |
| --- | --- |
| `Test.Assert(condition)` | Записывает успех или ошибку и продолжает выполнение. Перегрузка принимает отдельные сообщения для обоих исходов. |
| `Test.Assert(condition, failureMessage)` | Записывает только ошибку при ложном условии и продолжает выполнение. При успехе ничего не выводит. |
| `Test.Require(condition, message)` | Выбрасывает исключение при ложном условии. |
| `Test.Throws<T>(action)` | Выполняет синхронное действие и возвращает исключение типа `T` или производного типа. Если исключения нет, останавливает тест с ошибкой; исключение другого типа передаёт без изменений. Не записывает сообщение при успехе. `null` вместо действия вызывает `ArgumentNullException`. |
| `Test.RequireContains(message, fragments)` | Проверяет наличие всех фрагментов в строке с помощью `StringComparison.Ordinal`. Останавливает тест на первом отсутствующем фрагменте; при успехе ничего не выводит. |
| `Test.Success(message)` | Записывает сообщение об успехе. |
| `Test.Fail(message)` | Помечает текущий тест непройденным и продолжает выполнение. |
| `Test.Warning(message)` | Записывает предупреждение без изменения статуса теста. |

Необработанное исключение делает тест непройденным; следующие методы продолжают выполняться. Метод без ошибок считается пройденным. Для каждого провайдера выводится сводка пройденных, непройденных и пропущенных методов. Счётчики учитывают методы, а не отдельные проверки сигнатур; между блоками контекст сбрасывается.

Консоль открывается через встроенный Windows PowerShell. Закрытие окна не завершает Robur и не прерывает тесты. Вывод продолжается в фоне после завершения команды; при разрыве соединения консоль сообщает о возможной неполноте отчёта.
